# 云函数规范（cloudfunctions/）

## 基本形态

- 每个云函数一个目录：`index.js` + `package.json`（`wx-server-sdk ~2.6.3`），需要 openapi 权限时另配 `config.json`
- 初始化一律 `cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })`，禁止硬编码环境 ID（前端 App.vue 那处写死是另一约定，勿混淆）
- 入参不信任：roomId 等关键字段缺失直接 throw；涉及内容展示的字段过 `checkContent` 云函数校验

## 错误约定（与前端 cloudErrMsg 配套）

- 业务错误用 `throw new Error('中文业务文案')`；前端 `cloudErrMsg` 靠 `errMsg: Error: <文案>` 段提取，所以文案写在 Error 首行，不要在文案前拼其他前缀

## 数据模型与核心语义

| 集合 | 说明 |
|---|---|
| rooms | 房间主表。`status`：`gaming` / `settling` / `settled` / `dissolved`。`memberCount` 是在场人数，进房退房改这一份文档。进行中房号不靠查表判重 |
| room_members | 成员表。**退房是软删（写 leftAt，并把 `active` 改为 false），重进新插一条**。是否在场只查 `active == true`（`limit(1)`），不要把历史记录一次性取回 |
| room_codes | 文档 `_id` 为 `rc` + 房号（4 位房号直接当 id 时云开发会拒写）。建房时插入，重复就换码；结算或解散时删除，旧号可以复用。客户端不可读写 |
| game_records | 记账流水，**append-only 只增不删**。客户端不可读写。单笔 1–999999；单房条数有上限，超出拒绝并提示先结算 |
| settlements | 结算快照。同一房间文档 `_id` 用 roomId，避免并发确认写出两份。客户端不可读写 |
| rate_limits | 进房失败、连续记账的次数窗口。文档 id 为 `join_<openid>` 或 `xfer_<roomId>_<openid>`。客户端不可读写 |
| app_config | 固定文档 `home_qr` 存首页小程序码 fileID，只生成一次。客户端不可读写 |

权限（控制台，云函数管理员写入不受限）：

- `users`：仅创建者可读写。前端 `get()` 不加 where，靠这条权限只取到自己
- `game_records`、`settlements`、`room_codes`、`rate_limits`、`app_config`：所有用户不可读写
- `rooms`、`room_members`、`messages`：房间页要 `watch`，不要收成仅创建者
- 云存储：所有用户可读，仅创建者可写（否则别人的 `cloud://` 头像空白）

- 记账/结算语义：成员半路退出再回来，账目必须连续——净额汇总看全部 game_records，退出成员照常进结算名单（欠账不消失）；settle 取昵称头像**按 joinedAt 升序分页读完，后写覆盖**
- 结算与转账互斥：云开发事务不能跨集合同时写 `rooms` 和 `game_records`。settle 用 `where({ status: 'gaming' })` 把状态改成 `settling`，transfer 写流水前用同一条件更新房间；`updated === 0` 就拒绝。卡在 `settling` 时房主可再次确认把这局结完
- 快照类落库（settlements）字段必须带兜底（昵称空 → '牌友'），旧版本快照可能缺字段，前端展示也要再兜一层
- 房间码：createRoom 用 `qrcode` 包（^1.5.4）生成**纯文本普通二维码**，内容 `请在小程序内点击「扫码进房」加入牌局，房号：XXXX`——站内 wx.scanCode 可靠读出；真机扫小程序码拿不到内容是微信平台限制（详见 06），勿改回小程序码方案。邀请文案不能写成「微信扫一扫即可加入」

## 部署

- 微信开发者工具里右键云函数目录 → 上传并部署；**改了 package.json 依赖必须选「云端安装依赖」**
- 根目录 `cloudfunctions/` 由 vite 插件自动同步进 `dist/*/mp-weixin/cloudfunctions`，开发者工具从产物目录识别；本地语法检查用 `node --check cloudfunctions/<name>/index.js`
- 改动是否需要重新部署：云函数改了 → 部署对应函数；纯前端改动 → 只需重新编译小程序。回复用户时主动说明这一点
