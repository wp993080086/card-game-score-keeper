# 构建与平台限制

## 构建链路

- `npm run dev:weixin`（watch）/ `npm run build:weixin`（一次性），产物分别在 `dist/dev/mp-weixin`、`dist/build/mp-weixin`
- vite.config.js 的 `cloudfunctionsSyncPlugin` 自动把根目录 `cloudfunctions/` 同步进产物（dev 下监听 + 300ms 防抖）；uni 与开发者工具只读产物，勿向产物写文件
- `npm run postinstall` 跑 `scripts/fix-glob-eager.js`（修 uni 插件 glob 兼容），重装依赖后自动执行，勿删
- **验证标准**：前端改动以 `npm run build:weixin` 通过 + 产物抽查为准；`npm run lint` 脚本已坏（`--ignore-path` 在 eslint 9 移除），修复前不作验证手段
- 产物验证要点：不只看命令退出码，抽查被改页面的 wxss/wxml 是否生成、关键类名/样式是否进入产物（grep 产物文件）

## 微信平台已知限制（踩实了的坑，勿当 bug 修）

| 现象 | 结论 |
|---|---|
| 真机 `uni.scanCode` 扫**小程序码**：`res.path` 为 undefined、`res.result` 为 `*` 占位（安卓居多） | 微信平台限制，代码无解。房码已改普通二维码方案；站内扫码解析统一走 home 页 `_resolveRoomCode`（兼容 scene= / roomCode= / 纯房码 / 「房号：XXXX」文本） |
| `wx.showShareImageMenu` 的 success/fail 只反映面板弹出/取消，用户在面板内点「保存图片」**无任何回调** | 平台限制。精准的保存反馈必须走 `wx.saveImageToPhotosAlbum`（utils/poster.ts 已封装：成功 toast、取消静默、授权被拒引导 openSetting） |
| 小程序 `canvas 2d` 无法离屏创建 | 战绩图用屏外画布：`position: fixed; left: -9999px` + 固定 px 宽高的 `<canvas type="2d">`，绘制导出走 `wx.canvasToTempFilePath` |
| 开发阶段小程序码 `getUnlimited` 报页面未发布 | `checkPath: false`（settle 云函数首页码场景） |

## 发布相关

- 真机验证新前端：微信开发者工具上传 → 设为体验版（或提审发布）
- 房码为普通二维码：外部「微信扫一扫」只显示提示文本（含房号，可手输进房）；将来要外部直达需换普通链接二维码 + mp 后台规则（需备案域名，用户已明确不申请）
