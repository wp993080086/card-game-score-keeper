# 编码规范

## Vue 写法

- 页面/组件一律 `<script setup lang="ts">`，禁止 Options API（`data`/`methods`/`computed` 选项、`mixins`、`this`）；例外仅 `src/App.vue`
- 复用逻辑写成 `useXxx` composable 放 `src/utils/`（如 `useAvatarFallback`）
- 组件名用 `defineOptions({ name: 'XxxYyy' })` 声明
- props / 事件用 `defineProps` / `defineEmits`；v-model 用 `modelValue` + `update:modelValue`
- 生命周期从 `@dcloudio/uni-app` 导入：`onLoad` / `onShow` 等（区别于 vue 的 `onMounted`）
- 多平台条件编译用 `// #ifdef MP-WEIXIN` 注释块

## TypeScript

- `tsconfig` 开 strict，路径别名 `@/*` → `src/*`
- 全局类型在 `src/types/commom.d.ts`（注意目录名拼写就是 `types/commom.d.ts`）：`TAny` / `TDict<T>` / `TFunc` / `I_DbQuery`，直接使用不重复定义
- 接口命名 `I_` 前缀（如 `I_NetScore`）；不为了类型而过度建模，响应模型贴云函数实际返回

## 注释风格

- 中文注释；每个函数/变量声明上方用 JSDoc 单行：`/** @description 做什么*/`（`*/` 紧贴，项目既有风格）
- 「为什么这么写」的坑点注释保留价值高，新代码踩过坑要补注释（见 04-样式规范的头像/弹窗条目）

## 云调用与错误处理

- 云函数调用统一走 `src/apis/` 按域拆分（`cloud.ts` 基础封装 / `room.ts` / `game.ts` / `user.ts`），组件禁止直接 `wx.cloud.callFunction`
- 基础封装 `callCloud<T>(name, data)` 在 `src/apis/cloud.ts`；云函数 throw 的错误用同文件的 `cloudErrMsg(err)` 提取业务短文案，直接进 toast：`uni.showToast({ title: \`xx失败：${cloudErrMsg(err)}\`, icon: 'none' })`
- 失败流程必须 `console.error('[页面/模块] 发生了什么:', err)` 留日志再提示
- loading 类提示（`uni.showLoading`）在 then/catch/finally 都要 `uni.hideLoading()`，防卡死

## 云数据库（前端直查场景）

- 集合权限分两类：机密数据（room_members / game_records / settlements）**只经云函数读写**；登录态下自己的 users 记录可前端直查
- 前端直查用 `wx.cloud.database()`，链式 where/orderBy/limit 后 `.get()`；实时监听用 `.watch()`（类型见 `I_DbQuery`）
